# Cornerstone Tint Vehicle & Property Protection Guide

A dependency-free, five-page static website prepared for GitHub Pages. The site presents educational content about Cornerstone Tint & Paint Protection, connects each service to the surface and customer goal it addresses, and provides a deliberate internal-link structure across every page.

## Pages

| File | Purpose |
| --- | --- |
| `index.html` | Main entity and protection guide, comparison table, services, brands, service areas, reviews, map, and official-site preview |
| `paint-protection-film.html` | Paint protection film, coverage priorities, matte PPF, Tesla PPF, and connections to coating and tint |
| `ceramic-coating.html` | Keramik-X ceramic coating, preparation, maintenance, PPF comparison, and connected protection planning |
| `window-tinting.html` | Automotive, Tesla, Cybertruck, residential, commercial, privacy, and decorative window film |
| `locations.html` | Overland Park business location, Google map, hours, surrounding service areas, customer reviews, and contact information |

Every page links to every other page through the primary navigation and footer. Contextual internal links also connect related concepts inside the educational copy.

## GitHub Pages deployment

1. Create a GitHub repository, preferably named `cornerstone-tint-guide`.
2. Upload the complete contents of this folder to the repository root.
3. In the repository, open **Settings → Pages**.
4. Under **Build and deployment**, select **Deploy from a branch**.
5. Select the `main` branch and the `/ (root)` folder, then save.
6. GitHub will publish the site at a URL similar to:
   `https://YOUR-GITHUB-USERNAME.github.io/cornerstone-tint-guide/`
7. Replace `YOUR-GITHUB-USERNAME` inside `sitemap.xml` with the actual GitHub username after publishing.
8. If a custom domain is added later, update the sitemap URLs and add the final canonical URL to each page.

There is no build command and no package installation. The `.nojekyll` file tells GitHub Pages to serve the files as written.

## Structured data

The site uses JSON-LD only when it matches visible content:

- Homepage: `WebSite`, `WebPage`, `LocalBusiness`, `Organization`, `PostalAddress`, `GeoCoordinates`, `OpeningHoursSpecification`, `OfferCatalog`, `Offer`, and `Service`
- Service pages: `WebPage`, `Service`, `LocalBusiness`, and `PostalAddress`
- Location page: `WebPage`, `LocalBusiness`, `Organization`, `PostalAddress`, `GeoCoordinates`, and `OpeningHoursSpecification`

The business has a consistent `@id` of `https://www.cornerstonetint.com/#business`. The official website is the entity URL, the Google Business Profile is supplied through `hasMap`, and social profiles are supplied through `sameAs`.

No fabricated price range, rating, review count, warranty, or aggregate rating is included. Test the deployed pages with the Schema.org Validator and Google Rich Results Test after publishing.

## SEO and content notes

- The content is educational and organized by surface, concern, service, product partner, and service area.
- Internal anchor text is descriptive but not repetitively optimized.
- Location links appear in relevant service-area context.
- Service links appear where the corresponding service is explained.
- Review links identify the reviewer and project instead of using keyword-stuffed anchors.
- The site does not use hidden text, doorway pages, duplicated city pages, or automated keyword blocks.
- A microsite or backlink cannot guarantee rankings or authority transfer.
